RevokAI — Governed Access Control

A governed AI compliance control for access revocation: AI correlates, rules and a human decide, and every action is evidenced.

Problem

Access-revocation compliance controls rely on manual analysis. The hardest step is matching people who have left to the accounts they still hold, because the identifiers often sit in metadata and free text where a standard report can't join them. That matching is slow human work, and the control costs roughly 25 hours a week to run manually.

What it does

RevokAI turns the manual control into a closed loop with five stages: detect, validate, approve, remediate, prove. An AI agent matches leavers to accounts even where the match is buried in metadata or free text. Fixed rules apply the revocation deadline (SLA), and each exception ends up in a named outcome. A human approves every remediation action. Every action is ticketed and timestamped, and each run produces an audit trail that can be exported. I co-built RevokAI in a sponsored squad, contributing the agent workflow and its run outputs.

Value

It is designed to turn an access-revocation control from a weekly manual grind into an on-demand run that takes minutes and produces its own audit trail. It targets the roughly 25 hours a week (about 1,300 hours a year) that the control costs to run manually today. That figure is the current manual cost, not a measured saving. The same pattern (AI reasons, fixed rules decide, humans approve the action) carries over to other controls such as access recertification.

FlowHow a request moves through it

  1. 1Step 1: Detect: the loop takes in leaver records and the account data to check them against.
  2. 2Step 2: Validate (AI): the matching agent links leavers to accounts where identifiers are buried in metadata or free text.
  3. 3Step 3: Validate (rules): fixed rules apply the revocation deadline.
  4. 4Step 4: Validate (outcome): each exception lands in a named outcome: breach, within SLA, compliant, or for review.
  5. 5Step 5: Approve: a human reviews each proposed remediation. Nothing goes ahead without approval.
  6. 6Step 6: Remediate: each approved action is raised as a remediation ticket.
  7. 7Step 7: Prove: every action is ticketed and timestamped, and the run is compiled into an audit trail that can be exported as control evidence.
